# 5.1 — Android build: the app runs as a worker

**Result: `npm run tauri android build -- --target aarch64 --apk --debug` succeeds. The app runs on Android as an RPC worker. The Mac (both the engine's command-line host and the Mac app) hosted `qwen3.5-0.8b` split across the Mac and the Android device, and chat worked.**

**Tested on an Android emulator, not a phone.** No Android phone was available, so the device is the official Android Emulator running an arm64 Android 14 image on the MacBook Air. Everything ran the real app, real engine and real model, but expect these differences from a phone:
- **Network:** the emulator sits behind its own NAT (10.0.2.16), so the Mac reached its worker through `adb forward tcp:50062 tcp:50052`. The worker therefore shows as `RPC[127.0.0.1:50062]`, not as a Wi‑Fi address.
- **Speed:** the CPU is the Mac's, virtualised, so tokens/s don't reflect a phone.

Repeat this on a phone before release (Task 6.1).

## Build

- `engine/build.rs`:
  - Android branch using the NDK's CMake toolchain (`ANDROID_ABI=arm64-v8a`, `ANDROID_PLATFORM=android-28`);
  - CPU backend, Metal off;
  - `GGML_CPU_ARM_ARCH=armv8.2-a+dotprod+fp16`;
  - the C++ runtime linked statically.
- The APK is 236 MB (a debug build that keeps symbols). Its `libdistllm_app_lib.so` needs only system libraries: `liblog`, `libandroid`, `libdl`, `libm` and `libc`.
- `minSdk` is 28. The manifest adds `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE`, `CHANGE_WIFI_MULTICAST_STATE` and `WAKE_LOCK`.

## Worker

Tapping Worker on the emulator ([screenshot](5.1/android-worker.png)) gave:

```
Serving layers at 0.0.0.0:50052 (CPU). Switch to Idle to stop.
CPU: CPU (3922 MiB, 2135 MiB free)        # worker log (logcat)
tcp  0.0.0.0:50052  LISTEN                # netstat on the emulator
```

Free memory comes from `MemAvailable` (`patches/llama.cpp/0003-…`). Unpatched llama.cpp reports all of RAM as free on Linux and Android.

## The Mac hosts with the Android worker

**Engine command-line host** (`engine/examples/host.rs`, new):

```
$ host models/Qwen3.5-0.8B-Q8_0.gguf 127.0.0.1:50062 -- "What is the capital of France? Answer in one sentence."
loaded in 5400 ms
  127.0.0.1:50062                 84.35 MiB  layers 0-3
  Apple M5                       679.43 MiB  layers 4-25
> What is the capital of France? Answer in one sentence.
The capital of France is Paris.
7 tokens in 134 ms (52.2 tokens/s), stopped: Eos
```

llama.cpp's own report: `RPC0[127.0.0.1:50062] model buffer size = 84.35 MiB`. The worker's log shows the tensors arriving (`[set_tensor] saved to '/data/user/0/com.distllm.app/cache/rpc/…'`).

**Mac app.** Driven through its interface:
1. Devices: Idle, then "Add by address" `127.0.0.1:50062`, then switched it on.
2. Chat: Qwen3.5 0.8B, then Load.

The split dock then read:

| Device | Layers | Model buffer |
|---|---|---|
| 127.0.0.1:50062 (the Android emulator, RPC) | 0–4 | 106.3 MiB |
| This device (Mac) | 5–25 | 657.5 MiB |
| Total | | 763.8 MiB |

The header read "On 127.0.0.1:50062 and this device". The question "Name three planets in our solar system, in one sentence." came back as "The Sun, Mercury, and Earth are three planets in our solar system." at 39.6 tokens/s. That is the 0.8B model's own answer, Sun included, recorded as given.

The two hosts split differently (layers 0–3 vs 0–4) because llama.cpp splits by the free memory each device reports at load time, and that had changed between the runs.

Downloaded in the app (Models → Download): `Qwen3.5-0.8B-Q8_0.gguf`, 833,592,096 bytes, checksum verified, status Ready ([screenshot](5.1/android-models-download.png)). Cancel and Resume worked too, on the 2B model.

## Found and fixed during this run

| Problem | Fix |
|---|---|
| `engine/src/host.rs` didn't compile for Android: `*const i8` where ARM Linux's `c_char` is `u8` | Use `std::ffi::c_char` |
| Android's free memory showed as all of RAM | llama.cpp patch 0003, `MemAvailable` |
| The device's name would have been "unknown" (Android apps see the hostname "localhost") | Maker and model from system properties |
| The gesture bar covered the bottom tabs, and the keyboard covered the composer: WebView 113 provides no `env(safe-area-inset-*)` | `MainActivity` passes the real insets (status bar, gesture bar, cutout, keyboard) as CSS variables (`src/app/insets.ts`) |
| Status bar icons were dark on the dark theme | Bar icons follow the app's theme |
| Searching animation blank: a frame's timestamp before the start time gave rings a negative radius, and canvas threw | Elapsed time clamped at 0 |
