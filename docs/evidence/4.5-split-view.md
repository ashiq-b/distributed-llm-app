# 4.5 — Split view

**Result: hosting on the Mac and on the iPhone, the split view showed one row per device with llama.cpp's own layer ranges and buffer sizes. The numbers are read from llama.cpp's load log; for Qwen3.5 2B the total on device (1,211.0 MiB, Mac + iPhone) equals the total llama.cpp logs for the same model split three ways on one Mac (1,211.04 MiB).**

Both splits cover every layer with no gap (25 layers for Qwen3.5 2B, 26 for 0.8B), and the bars match the percentages. Workers are shown by the name they announce, not their address.

## Against llama.cpp's log

The engine reads each device's share from llama.cpp's `load_tensors: … model buffer size = … MiB` lines (`engine/cpp/dl_stats.cpp`). `engine/tests/split.rs` with `DL_TEST_MODEL=models/Qwen3.5-2B-Q4_K_M.gguf`, two local RPC workers plus the Mac's GPU:

| llama.cpp log line | Parsed share |
|---|---|
| `RPC0[127.0.0.1:53398] model buffer size = 308.00 MiB` | worker, layers 0–8, 308.0 MiB |
| `RPC0[127.0.0.1:53401] model buffer size = 264.79 MiB` | worker, layers 9–16, 264.79 MiB |
| `MTL0_Mapped model buffer size = 397.86 MiB` + `MTL0_Mapped … = 240.39 MiB` | Apple M5 (local), layers 17–24, 638.25 MiB |
| `CPU_Mapped model buffer size = 397.85 MiB` | not counted (the host's mapped copy of the file) |

Total 1,211.04 MiB, the same as the on-device Mac + iPhone total for this model.

These lines were captured by the engine and not printed, so the app's own log had nothing to compare. From this commit the engine also prints them (buffer sizes and `offloaded N/N layers`) to the app's log.
