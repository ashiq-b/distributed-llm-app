# 0.2 — Catalog models: real split over llama.cpp RPC (command line)

**Result: all three catalog models split correctly. Killing the worker aborts the host process.**

## Setup

| | |
|---|---|
| llama.cpp | v1.0.0 (`b1b770d9`), RPC protocol 10.0.0 |
| Machine | Apple M5, macOS, Metal (`MTL0`) |
| Host | `llama-completion` (in v1.0.0, raw completion moved here from `llama-cli`) |
| Worker | `ggml-rpc-server -H 127.0.0.1 -p 50052`, a separate process on the same Mac |
| Common args | `-ngl 99 -c 4096 -v -no-cnv -p "The capital of France is" --temp 0 --seed 1 -n 16` |
| Reproduce | `scripts/fetch-model.sh <id>` then `scripts/cli-split-check.sh <id>` |

- Host and worker run on one Mac, so both devices report the same free memory. llama.cpp therefore splits roughly in half. On real phone/laptop pairs, the split follows each device's free memory.
- `-c 4096` is set explicitly. These models' default context is 262,144 tokens, which would reserve unrealistic memory.

## Killing the worker mid-generation

The host was generating (2000 tokens, `--ignore-eos`). After 75–117 bytes of output, the worker was killed with `kill -9`.

| Model | Host result |
|---|---|
| All three | **Process aborted** (exit 134, SIGABRT) within ≤ 1 s. It did not hang. |

```
ggml/src/ggml-rpc/ggml-rpc.cpp:696: Remote RPC server crashed or returned malformed response
E recv failed (bytes_recv=0, size_to_recv=8)
  ggml_abort ← rpc_dispatcher::work   (dispatcher thread)
```

The abort comes from `RPC_STATUS_ASSERT(status)` in `rpc_dispatcher::work` after a failed `send_rpc_cmd`; the file has 4 such abort sites. There is no error-return path at v1.0.0.

**Impact:** inside our app, a worker dropping out will **crash the host app**, including on the iPhone. This triggers the ⚠️ decision in Task 1.3. The options are (a) accept the crash and show "worker disconnected" on relaunch via a crash marker, or (b) a small documented patch to ggml-rpc that turns the abort into an error. That needs the user's approval.

## Decision point

No model needed replacing. All three load and split, and produce coherent, identical output in split mode at the pinned commit.
