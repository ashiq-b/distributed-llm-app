## Stopping a worker

llama.cpp v1.0.0 has no call to stop its RPC server (its accept loop runs until accept fails). `dl_worker_stop` finds the server's listening socket and accepted connections among the process's own descriptors (TCP, local port = worker port) and:

- wakes `accept()`: `shutdown()` does on Linux and Android; on macOS and iOS `shutdown()` fails on a listening socket with `ENOTCONN`, but replacing the descriptor with `dup2()` makes `accept()` return `ECONNABORTED` (checked with a small C program on macOS before using it);
- shuts down any host's connection, so the server stops serving and frees that session's buffers.

The server thread returns and the worker can start again. `engine/tests/worker.rs` `worker_lifecycle` covers it: a connected host's socket reads EOF, the port refuses connections, and a new worker starts on the same port.

If a host is connected when the user leaves Worker, the app asks first (`worker_hosts`), since that host's model stops working.
