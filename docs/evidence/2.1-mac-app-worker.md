# 2.1 — DistLLM app (macOS) as an RPC worker

**Result: the app's in-process worker held a real share of a model loaded by llama.cpp's own host.**

| | |
|---|---|
| App | `DistLLM.app` (debug bundle, `npm run tauri build -- --debug --bundles app`) |
| Action | "Start worker" clicked in the app's window (port 50052, bound to all interfaces) |
| Host | `llama-completion -m Qwen3.5-0.8B-Q8_0.gguf -ngl 99 -c 1024 -v --rpc 127.0.0.1:50052 -p "Hi" -n 8 --temp 0` |

The listening socket belongs to the app process, on all interfaces (reachable from the LAN):
```
distllm-a 9039 ashiq 10u IPv4 … TCP *:50052 (LISTEN)
```

The host's load log shows the app holding layers 0–12:
```
load_tensors: layer   0 assigned to device RPC0, is_swa = 0
load_tensors: layer  12 assigned to device RPC0, is_swa = 0
load_tensors: layer  13 assigned to device MTL0, is_swa = 0
load_tensors: layer  25 assigned to device MTL0, is_swa = 0
load_tensors:  MTL0_Mapped model buffer size =   257.66 MiB
load_tensors:  MTL0_Mapped model buffer size =   231.14 MiB
load_tensors: RPC0[127.0.0.1:50052] model buffer size =   274.98 MiB
```

The host exited 0 and generated `Hi, I have a question about the following`.

The 274.98 MiB matches the Phase 0 CLI worker and the engine tests for the same model.
