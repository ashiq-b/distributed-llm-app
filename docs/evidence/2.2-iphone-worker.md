# 2.2 — DistLLM on iPhone as an RPC worker (over Wi‑Fi)

**Result: the iPhone app held a real share of a model loaded by a host on the Mac, over home Wi‑Fi. The output matched the single-device run.**

| | |
|---|---|
| iPhone | iPhone 15 (A16), iOS app `com.distllm.app`, debug build, signed by the free personal team `5VQ74NGWQF` |
| Engine | llama.cpp v1.0.0 + our patch, cross-compiled for `aarch64-apple-ios` (iOS ≥ 16.4, Metal embedded), linked in-process |
| Network | Mac `192.168.1.7` ↔ iPhone `192.168.1.3`, same Wi‑Fi |
| Action | App opened on the iPhone, Local Network allowed, "Start worker" tapped |
| Host (Mac) | `llama-completion -m Qwen3.5-0.8B-Q8_0.gguf -ngl 99 -c 1024 -v --rpc 192.168.1.3:50052 -p "The capital of France is" -n 16 --temp 0 --seed 1` |

## What llama.cpp reported

The iPhone's GPU reports a 4096 MiB working set (3901 MiB free at load). llama.cpp split by free memory, so the iPhone got 7 of 26 layers:

| Device | Layers | Model weights | KV cache | Compute buffer |
|---|---|---|---|---|
| iPhone (`RPC0[192.168.1.3:50052]`) | 0–6 | **150.10 MiB** | 2.00 MiB | 35.40 MiB |
| Mac (`MTL0`) | 7–25 | 356.02 MiB (+257.66 MiB tied embedding map) | — | — |

```
llama_prepare_model_devices: using device RPC0 (192.168.1.3:50052) (unknown id) - 4095 MiB free
load_tensors: layer   0 assigned to device RPC0, is_swa = 0
load_tensors: layer   7 assigned to device MTL0 …
load_tensors: RPC0[192.168.1.3:50052] model buffer size =   150.10 MiB
llama_kv_cache: RPC0[192.168.1.3:50052] KV buffer size =     2.00 MiB
```

## Output and speed

Output was byte-identical to the single-device baseline from 0.2:
```
The capital of France is Paris.
The capital of France is Paris.
The capital of France is
```
Over Wi‑Fi: decode 14.6 tok/s (68 ms/token) versus about 129 tok/s on a single Mac. This is the expected network cost; speed is not a goal. The total run took 67 s, including sending the iPhone's 150 MiB share over Wi‑Fi.

## Decision point: increased memory limit entitlement

Adding `com.apple.developer.kernel.increased-memory-limit` and building with the free team fails:
```
Provisioning profile "iOS Team Provisioning Profile: com.distllm.app" doesn't include the Increased Memory Limit capability.
```
**Not available with a free account.** The iPhone hosts within the default app memory limit. It reports a 4 GB GPU working set, and the largest catalog model peaks at about 1.6 GB on a single device (0.2). Whether each model fits when the iPhone hosts is checked in Task 2.4.

## Build notes

- Xcode needs Apple's Accelerate framework (BLAS/vDSP used by llama.cpp). Rust's framework links don't reach Xcode's final link, so `Accelerate.framework` is added to `gen/apple/project.yml`. Re-add it if the iOS project is ever regenerated with `tauri ios init`.
- `rustup`'s toolchain must come before Homebrew's `rust` on `PATH`. Homebrew's has no iOS std library.
