# 2.4 — P0 milestone: iPhone ↔ Mac split, both directions

**Result: the iPhone hosted a model split with the Mac as worker, and the Mac hosted one split with the iPhone as worker. Multi-turn chat worked both ways. When the worker's Wi‑Fi dropped, the host reported the loss and stayed open, and a reload then worked.**

| | |
|---|---|
| Devices | iPhone 15 (A16) and a MacBook (Apple M5), same home Wi‑Fi |
| App | DistLLM debug builds (this commit), engine = llama.cpp v1.0.0 + patch 0001 |
| Network | Mac `192.168.1.2`, iPhone `192.168.1.4`, worker port `50052` |
| Screen | Temporary screen: endpoint field, model select, Load, shares table, chat (multi-turn, `<think>` blocks stripped from history) |

## iPhone host, Mac worker (`lfm3-1.7b`)

Shares as reported by llama.cpp's load log (shown in the app):

| Device | Layers | Model buffer |
|---|---|---|
| Mac (`RPC0[192.168.1.2:50052]`) | 0–18 | **654.58 MiB** |
| iPhone (Metal, local) | 19–24 | 386.24 MiB |

- A 3-turn chat worked; one answer was 172 tokens in 17.2 s (about 10 tok/s over Wi‑Fi).
- Load (sending the Mac's share over Wi‑Fi) took 1–3 minutes.

## Mac host, iPhone worker (`lfm3-1.7b`)

| Device | Layers | Model buffer |
|---|---|---|
| iPhone (`RPC0[192.168.1.4:50052]`) | 0–6 | **246.28 MiB** |
| Mac (Metal, local) | 7–24 | 794.54 MiB |

- A 3-turn chat worked.

The split follows each device's free memory: the Mac reports more free memory, so it takes more layers whichever side hosts.

## iPhone host: the other catalog models

`qwen3.5-2b` and `qwen3.5-0.8b` each loaded on the iPhone split with the Mac as worker and answered a question (reported working by the tester; their shares tables were not recorded).

## Worker loss

| Case | Result |
|---|---|
| Mac's Wi‑Fi turned off while the iPhone was hosting and answering | iPhone showed `Error: lost connection to worker 192.168.1.2:50052`; the app stayed open |
| Wi‑Fi back on, iPhone taps Load again with the same worker | Loaded to 100% and chat worked again (no stuck worker) |
| Quitting the Mac app (Cmd+Q) mid-answer | **Not tested yet.** Carried to Task 3.4, where it is checked together with role changes |

## Not recorded

- Screenshots were not captured; the tables above were copied from the app's shares table.
- Memory on the iPhone while hosting was not measured. That is part of the Phase 7 benchmarks.
