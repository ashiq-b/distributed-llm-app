## How thinking is switched off

`llama_chat_apply_template` (the built-in templates) ignores each model's `enable_thinking` switch, so the engine adds what each model's own Jinja template adds:

| Model | Thinking off (prompt ends with) | Thinking on |
|---|---|---|
| Qwen3.5 0.8B / 2B | `<think>\n\n</think>\n\n` | `<think>\n` |
| LFM3 1.7B | `<think></think>` | `<think>` |

LFM3 reasons anyway after `<think></think>`. llama.cpp's own `llama-completion --jinja --reasoning off` shows the same. So with thinking off, the `<think>` and `</think>` tokens are also banned in the sampler. With thinking on, the opening tag is streamed to the app so the reasoning is shown as `<think>…`.

Also fixed: the built-in templates leave out BOS, which LFM3's template starts with. The engine now adds BOS when the model's vocabulary asks for it.

Thinking off, greedy, on the Mac (`think_off_answers_without_thinking`, "What is the capital of France? Answer in one word."):

| Model | Before (thinking) | After |
|---|---|---|
| LFM3 1.7B | `<think>The user asks: …</think>Paris`, 59 tokens | `Paris`, 1 token |
| Qwen3.5 0.8B | thought by default | ` Paris`, 1 token |
| Qwen3.5 2B | thought by default | `Paris`, 1 token |

## Answer length

`max_tokens` is now 2048 (was 512), capped by what the 4096-token context has left after the conversation. A conversation that leaves fewer than 256 tokens is refused with "start a new chat".

## Seen on device, for a later task

Loading `lfm3-1.7b` on the iPhone with the Mac as worker took about 4–5 minutes. The Mac's share (about 655 MiB, see 2.4) is sent over Wi‑Fi on every load. The worker's RPC cache only keeps tensors over 10 MB (llama.cpp's `HASH_THRESHOLD`): the Mac's cache held 8 files (98 MB), each a byte-for-byte copy of a tensor in the GGUF file.
